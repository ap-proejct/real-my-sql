## 1. 사용자 식별
- 사용자 계정뿐만 아니라 접속지점도 계정의 일부가 된다
  - 역따옴포(`) 또는 홑따옴표(')로 사용한다
  - `'svc_ic'@'127.0.01'`
- 모든 외부에서 접속이 가능한 계정을 생성하고 싶다면 호스트 부분을 `%`로 대체하면 된다
  - `'save_id'@'192.168.0.10'`
  - `'save_id'@'%'`
  - 만약 이런식으로 동일한 아이디가 있다면 범위가 작은 `192.168.0.10`을 선택하게 된다
  - 중첩된 계정을 생성하지 않도록 주의하자

## 2. 사용자 계정 관리
### 1. 시스템 계정과 일반 계정
- 8.0부터 `SYSTEM_USER`권한을 가지고 있냐에 따라 시스템 계정과 일반 계정으로 구분된다
  - 시스템 계정: 데이터베이스 서버 관리자를 위한 계정
    - 일반 계정을 관리(계정 생성 및 삭제 그리고 계정의 권한 부여 및 제거)
    - 다른 세션 또는 그 세션에서 실행중인 쿼리 강제 종료
    - 스토어드 프로그램 생성 시 definer를 타 상자로 설정
  - 일반 계정: 응용 프로그램이나 개발자를 위한 계정

>#### 내장된 계정
- `'mysql.sys'@'localhost'`: sys 스키마의 객체(뷰나 함수, 프로시저)들의 DEFINER로 사용된 계정
- `'mysql.session'@'localhost'`: MySQL 플러그인이 서버로 접근할 때 사용되는 계정
- `'mysql.infoschema'@'localhost'`: information_schema에 정의된 뷰의 DEFINER로 사용되는 계정

### 2. 계정 생성
- 계정 생성과 권한 부여를 구분해서 실행해야 한다
- 계정 생성 시 다양한 옵션을 설정할 수 있다
  - 계정의 인증 방식과 비밀번호
  - 비밀번호 관련 옵션(유효기간, 이력 개수, 비밀번호 재사용 불가 기간)
  - 기본 역할(Role)
  - SSL 옵션
  - 계정 잠금 여부

```sql
CREATE USER 'user'%'%'
  IDENTIFIED WITH 'mysql_native_password' BY 'password'
  REQUIRE NONE
  PASSWORD EXPIRE INTERVAL 30 DAY
  ACCOUNT UNLOCK
  PASSWORD HISTORY DEFAULT
  PASSWORD REUSE INTERVAL DEFAULT
  PASSWORD REQUIRE CURRENT DEFAULT;
```

#### 1). IDENTIFIED WITH
- 사용자 인증방식과 비밀번호를 설정한다
- 다양한 인증 방식을 플러그인 형태로 제공한다
  - Native Pluggable Authenticaiton: 5.7이전에 사용되던 방식으로 비밀번호 해시(SHA-1)값을 저장해두고 일치하는 방식이다
  - Caching SHA-2 Pluggable Authenticaiton(기본값): 위에와 알고리즘 차이이며 내부적으로 SALT를 활용하여 보안에 중점을 둔 알고리즘이다
    - SSL/TLS 또는 RSA 키페어를 필요로 하기 때문에 5.7버전과는 다른 방식으로 접속해야 한다
  - PAM Pluggable Authenticaiton: 유닉스나 리눅스 패스워드 또는 LDAP같은 외부 인증을 사용할 수 있게 해주는 인증 방식이다
  - LDAP Pluggable Authenticaiton: LDAP를 이용한 외부 인증을 사용할 수 있게 해주는 인증 방식이다

#### 2). REQUIRE
- MySQL 서버에 접속할 때 암호화된 SSL/TLS 채널을 사용할지 여부를 설정하다
- SSL로 설정하지 않았다고 하더라도 Caching SHA-2 Authentication 인증방식을 사용하면 암호화된 채널만으로 접속할 수 있게 된다

#### 7). ACCOUNT LOCK/ UNLOCK
- 계정 생서 시 또는 ALTER USER 명령을 사용해 계정 정보를 변경할 때 계정을 사용하지 못하게 잠글지 여부를 결정한다
- ACCOUNT LOCK: 계정을 사용하지 못하게 잠금
- ACCOUNT UNLOCK: 잠긴 계정을 다시 사용 가능 상태로 잠금 해제

## 3. 비밀번호 관리

### 2. 이중 비밀번호
- 계정의 비밀번호로 2개의 값을 동시에 사용할 수 있는 기능이다
- 최근에 설정한 비밀번호가 프라이머리 비밀번호이며, 이전 비밀번호가 세컨더리 비밀번호가 된다

```sql
-- 비밀번호를 old_password로 설정
ALTER USER 'root'@'localhost' IDENTIFIED BY 'old_password';

-- 비밀번호를 new_password로 변경하면서 기존 비밀번호를 secondary password로 유지
ALTER USER 'root'@'localhost' IDENTIFEID BY 'new_password' RETAIL CURRENT PASSWORD;
```

## 4. 권한
- 글로벌 권한과 객체 단위 권한으로 구분된다
- 글로벌 권한: 데이터베이스나 테이블 이외의 객체 적용되는 권한이다
  - GRANT 명령으로 특정 객체를 명시하지 말아야 하며 예외적으로 ALL은 글로벌과 객체 두 가지 용도로 사용될 수 있는데, 특정 객체에 ALL 권한이 부여되면 해당 객체에 적용될 수 있는 모든 객체 권한을 부여하며, 글로벌로 ALL로 사용되면 글로벌 수준에서 가능한 모든 권한을 부여하게 된다
- 객체 권한: 데이터베이스나 테이블을 제어하는 데 필요한 권한이다
  - GRANT 명령으로 특정 객체를 명시해야 한다. 

```sql
-- 글로벌 권한
GRANT SUPER ON *.* TO 'user'%'localhost';

-- DB 권한
GRANT EVENT ON employees.* TO 'user'%'localhost';

-- 테이블 권한
GRANT SELECT, INSERT, UPDATE, DELETE ON employees.* TO 'user'%'localhost';
GRANT SELECT, INSERT, UPDATE, DELETE ON *employees*.* TO 'user'%'localhost';

-- 특정 칼럼에 대해서만 권한을 부여할 수도 있다
-- 칼럼 단위 권한이 하나라도 설정되면 모든 칼럼을 검사하기 때문에 전체적인 성능에 영향을 미칠 수 있다
GRANT SELECT, INSERT, UPDATE(dept_name) ON employees.department TO 'user'%'locahost';

-- 권한 확인
SHOW GRANTS
```

## 5. 역할(Role)
- CREATE ROLE 명령을 이용해 정의한다
  - `CREATE ROLE role_emp_read, role_emp_write;`
- GRANT 명령으로 역할에 대해 실질적인 권한을 부여한다
  - `GRANT SELECT ON employees.* TO role_emp_read;`
  - `GRANT INSERT, UPDATE, DELETE ON employees.* TO role_emp_write;`
- 권한을 유저에게 부여
  - `GRANT role_emp_read TO reader@'127.0.0.1''`
  - `GRANT role_emp_read, role_emp_write TO writer@'127.0.0.1';`
- 기본적으로 역할의 권한을 사용하지 않는 상태이기 때문에 로그인할 때마다 `SET ROLE 'role_emp_read'`를 해줘야 한다
  - `activate_all_roles_on_login=ON;`을 해주면 항상 활성화 시켜준다
- MySQL 서버에서 역할과 계정은 동일한 객체로 취급된다
  - 내부적으로는 같지만 구분한 이유 중 하나로 역할은 `account_locked`가 Y로 설정되어 있어 로그인 용도로 사용할 수 없다
- 다른 사용자 계정 권한을 병합해서 권한 제어가 가능해졌을 뿐이다
- 역할을 부여할 뿐이라면 호스트 부분은 영향이 없다
- 하지만 다른 계정에 부여하지 않고 직접 로그인하는 용도로 사용한다면 그때 호스트 부분이 중요해진다

```sql
-- 뒤에 호스트 부분을 명시하지 않을 경우 모든 호스트(%)가 자동으로 추가된다
-- 계정과 역할을 아물너 차이가 없으며 role_ 이라는 prefix를 붙여 역할의 이름을 정하는 것이 좋다
CREATE ROLE
  role_emp_read,
  role_emp_write
```
